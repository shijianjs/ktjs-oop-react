<ktjs-features section-title="它能给你什么" tinted>

<ktjs-feature icon="lucide:boxes" title="没有 hook，也没有依赖数组">字段就是状态，方法就是回调。`useState`、`useCallback`、`useEffect` 以及它们的依赖列表在这里没有对应物，因为没有东西需要声明：可观察字段本身就是状态。</ktjs-feature>

<ktjs-feature icon="lucide:layout-grid" title="重渲染有边界">一个类可以有几个 `@OopReactRender` 方法，每个都是独立的岛：只订阅自己读到的字段，各自被一个错误边界包住，并按「实例 + 原方法 + 参数 + 名字」记忆化 —— 父岛重渲染不会带着子岛一起跑。</ktjs-feature>

<ktjs-feature icon="lucide:share-2" title="逻辑不搬家">对象相互持有，孙子可以直接写祖父的字段：不要 context、不要回调 prop、不要用 ref 一层层往下传。</ktjs-feature>

<ktjs-feature icon="lucide:flask-conical" title="状态类就是普通对象">`@OopReactState` 类是普通对象：可以在测试里 `new`，可以被别的类注入，可以完全脱离 React 使用。演示页的 Playwright 套件驱动的就是浏览器里那批类。</ktjs-feature>

<ktjs-feature icon="lucide:cog" title="可观察性就是 MobX">字段上的 `makeObservable`、集合的 `OopReactList`、修改方法的 action —— 没有自研的响应式层，字段没重绘时不必怀疑一层抽象。</ktjs-feature>

<ktjs-feature icon="lucide:triangle-alert" title="故障留在自己的岛里">每个岛自带错误边界：某个渲染方法抛了，就在它自己的位置显示一段信息，页面其余部分照常渲染。</ktjs-feature>

</ktjs-features>
