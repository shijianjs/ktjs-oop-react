<ktjs-features section-title="What you get" tinted>

<ktjs-feature icon="lucide:boxes" title="No hooks, no dependency arrays">Fields are state, methods are callbacks. `useState`, `useCallback`, `useEffect` and their dependency lists have no counterpart here, because there is nothing to declare: the observable field is the state.</ktjs-feature>

<ktjs-feature icon="lucide:layout-grid" title="Re-rendering has a boundary">A class can carry several `@OopReactRender` methods. Each one is its own island: it subscribes to the fields it reads, sits inside its own error boundary, and is memoised by instance, method and key — a parent island re-rendering does not drag its children along.</ktjs-feature>

<ktjs-feature icon="lucide:share-2" title="Logic stays where the objects are">Objects hold each other, and a grandchild writes its grandparent's field directly — no context, no callback props, no refs to thread through the tree.</ktjs-feature>

<ktjs-feature icon="lucide:flask-conical" title="The state classes are plain objects">A `@OopReactState` class is an ordinary object: construct it in a test, inject it into another class, use it without React at all. The demo's Playwright suite drives the same classes the browser does.</ktjs-feature>

<ktjs-feature icon="lucide:cog" title="Observability is MobX, not an abstraction">`makeObservable` on the fields, `OopReactList` for the collections, actions for the mutators. There is no bespoke reactivity layer to debug when a field does not repaint.</ktjs-feature>

<ktjs-feature icon="lucide:triangle-alert" title="Failures stay in their island">Each island carries an error boundary: a broken render method shows a message where it sits and leaves the rest of the page rendering.</ktjs-feature>

</ktjs-features>
